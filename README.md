# Агент-сметчик — ДЗ Шаг 1 (raw tool-calling на Anthropic SDK)

Агент считает смету по брифу клиента. Без LangChain, LangGraph и любых
agent-библиотек: только официальный `anthropic` SDK и обычный `while`.

## Записка об отрасли (контекст для преподавателя)

Я фрилансер-веб-разработчик: сайты, интернет-магазины, веб-приложения, CRM,
админ-панели, парсеры. Работаю в основном методом вайб-кодинга, поэтому
техническая часть перестала быть узким местом — узким местом стал **пресейл**.

Специфика, из которой вырос этот агент:

- **Оценка проекта — это не программирование, а рутина.** На входе бриф от
  клиента в свободной форме (письмо, голосовое, PDF). На выходе нужна смета по
  ролям: часы x ставка. Между ними — ручная работа: вычитать бриф, понять, какие
  роли задействованы, вспомнить ставки, посчитать, свести с бюджетом клиента.
  На один бриф уходит от 40 минут до нескольких часов.
- **Большая часть брифов не конвертируется.** Заявок много, оплаченных проектов
  мало, а считать приходится каждую. Это чистые невозвратные издержки.
- **С распространением нейросетевых инструментов конкурентов стало объективно
  больше.** Отстроиться самой разработкой уже трудно, а вот скоростью и
  качеством ответа на заявку — можно. Смета за минуту вместо «пришлю к концу
  недели» — это реальное конкурентное преимущество.
- **Ставки — коммерческая тайна и часто меняются.** Поэтому они лежат в
  локальном справочнике `data/rates.json`, а не в промпте: модель не должна их
  знать и тем более придумывать. Отсюда прямое требование к агенту: любую
  ставку берёт только инструментом, любой расчёт делает только калькулятором.

Дальняя цель — довести это до продукта: агент принимает заявку, ищет похожие
прошлые проекты, собирает смету и коммерческое предложение.

## Инструменты

| Инструмент | Что делает | Зачем в задании |
|---|---|---|
| `read_brief(filename)` | читает текстовый файл из `data/`, только оттуда | чтение локального файла |
| `get_rate(role)` | ставка по одной роли из `data/rates.json` | справочник, одна роль за вызов — чтобы получалась цепочка вызовов |
| `calculate(expression)` | арифметика через `ast`, **без `eval`** | безопасный калькулятор |
| `get_weather(city)` | заглушка с погодой | приманка: проверяет, что агент **выбирает** инструменты, а не вызывает все подряд |

## Как это работает

```
вопрос -> [ модель + список инструментов ]
              |
              +-- stop_reason == "end_turn"  -> финальный текст, выход
              |
              +-- stop_reason == "tool_use"  -> выполнить функции
                        |
                        +-- ок      -> tool_result
                        +-- ошибка  -> tool_result с is_error=true
                                            |
                                            v
                              всё дописывается в messages, новый оборот цикла
```

Важное: модель никогда не выполняет код. Она возвращает имя инструмента и
аргументы, выполняет их `agent.py`. API при этом stateless — на каждом обороте
вся история отправляется заново.

## Обработка ошибок

`execute_tool()` в `agent.py` не даёт процессу упасть никогда:

- `ToolError` — предсказуемая ошибка (нет файла, нет роли, деление на ноль);
- `TypeError` — модель передала не тот набор аргументов;
- любое другое исключение — ловится как непредвиденное.

Во всех случаях текст ошибки уходит модели как `tool_result` с
`is_error: true`, и модель получает шанс исправиться на следующем витке.
Сообщения об ошибках намеренно подсказывают выход — например, `get_rate`
перечисляет доступные роли.

## Запуск

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env      # и вписать свой ключ
python agent.py --test
```

`--test` прогоняет три сценария и складывает логи в `logs/`:

1. **Многошаговый**: прочитать бриф -> запросить ставки по каждой роли отдельно
   -> посчитать -> сверить с бюджетом клиента.
2. **Выбор инструментов**: «15% от 340, а потом тепло ли в Амстердаме» —
   пример из задания.
3. **Ошибки**: несуществующая роль и деление на ноль — агент получает ошибки,
   не падает и всё равно доводит задачу до конца.

Свой вопрос: `python agent.py "Посчитай смету по brief_shop.txt"`.

Модель по умолчанию — `claude-haiku-4-5` (дешёвая для отладки цикла),
переопределяется переменной `MODEL` в `.env`.
